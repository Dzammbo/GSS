# Канон: расчёт закупок материалов

## Назначение репозиториев
- Публичный `Dzammbo/GSS`: код расчёта, синтетические тесты и GitHub Actions **для синтетических или публичных входных данных**.
- Приватный `Dzammbo/gss-standards`: стандарты, реальные страницы Cynteka, контрольные точки, разметка и конфиденциальные результаты.
- В приватном репозитории не запускаем новые расчётные Actions; существующие независимые workflow не изменяем.

## Граница безопасности
Публичные Actions не должны скачивать, отображать в логах либо публиковать реальные платежи, счета и финансовые результаты. Токен к private repo в публичный workflow не передаём.

## Процесс
1. Постранично получить Cynteka с фиксированными фильтрами и датой среза.
2. Сохранить каждую страницу и подтверждённый курсор в private repo.
3. Доказать полноту: последняя страница имеет `next_page = null`.
4. Проверить плательщика и связанные счета, выделить и подтвердить материалы.
5. Исполнить открытый код обработки в защищённой среде и сохранить закрытые результаты в private repo.
6. В публичном Actions гонять синтетические тесты на каждый коммит.

## Состояние
Реальная выгрузка и полноценное сопоставление платежей со счетами ещё не реализованы. Текущий анализатор - консервативный прототип. Публичные Actions не обрабатывают приватные данные. Для автоматического расчёта больших закрытых наборов нужен отдельный защищённый исполнитель.
