# GSS - расчёт закупок материалов

Воспроизводимый расчёт фактически оплаченных закупок материалов АО «ГеоСпецСтрой» из Cynteka.

## Правила
- Используем только фактические платежи с `paymentDate` с 01.01.2026 по зафиксированную дату среза.
- Акцептация и плановые платежи не равны фактической оплате.
- Проверяем плательщика АО «ГеоСпецСтрой» по связанному счёту.
- Суммы с НДС; НДС отдельно при подтверждении данными.
- Материалы отдельно от услуг, работ, аренды, доставки, налогов и прочих расходов.
- Постраничная обработка до `next_page = null`; промежуточный результат не объявляется итогом.
- Контроль дубликатов, пропусков, сверка с исходными платежами.

## План воспроизводимого процесса
1. Фиксация даты среза, API-схемы и параметров выборки.
2. Постраничная выгрузка с сохранением курсоров и контрольных точек.
3. Проверка связанных счетов и плательщика.
4. Классификация операций с отдельным разбором спорных.
5. Расчёт, сверка, экспорт отчёта и фиксация версии.

## Безопасность
Репозиторий **публичный**. Запрещено публиковать реальные платежи, счета, контрагентов, реквизиты, секреты, сырые выгрузки и неразрешённые финансовые итоги. Фактические данные хранятся отдельно в приватном `Dzammbo/gss-standards` в выделенной директории `projects/material-purchases-2026/`. Публичный `GSS` содержит только код, методику и синтетические тестовые данные. Здесь допустимы код, методология и синтетические примеры. `.gitignore` не защищает данные, уже опубликованные в коммитах.

## Состояние
Открытый код `src/cynteka_pipeline.py` проверяет фактическую схему ГСС v2, даты оплаты, связанные счета, плательщика, валюты, НДС, конечность чисел и сверку позиций. `verify_export` проверяет сохранённые Git blob SHA, курсоры, стабильность total_count и уникальность ID. `stage_page` поддерживает повторное использование страницы после локального сбоя; транспорт должен фиксировать страницу и manifest одним атомарным коммитом и подтверждать main перед следующим запросом.

Реальная постраничная выгрузка и повторная сверка выполняются через ГСС v2 в защищённой сессии; закрытые данные, покрытие и результаты доступны только в выделенном проекте Private. Текущее состояние и нерешённые вопросы читать из его HANDOFF и manifest, а не из памяти чата. Полнота выгрузки платежей не подтверждает завершённость классификации или финансового расчёта.

Автоматический прямой API-транспорт и постоянный фоновый исполнитель не настроены. После завершения сессии выгрузка сама не продолжается. Public Actions выполняют синтетические тесты; конфиденциальные данные и токен к Private туда не передаются.

## Валидация
`python -m unittest discover -s tests -v`

Поддерживаемые категории: материалы, услуги, работы, аренда, доставка, налоги, командировочные и прочие расходы. Классификация требует свидетельства проверки позиций. Частично оплаченные смешанные счета распределяются пропорционально суммам проверенных позиций по явному решению пользователя от 09.10.2026. Распределение отмечается как расчётное, а не банковски подтверждённое. Неизвестный НДС не заменяется нулём. Отчёт валидатора всегда имеет `final_result: false` до отдельной полной сверки.
